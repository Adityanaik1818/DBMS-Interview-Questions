  <p align="left"><i><b>Brief:</b> Unlocks the rigid architectural rules that maintain database consistency and structural integrity.</i></p>
  <table width="100%" cellpadding="22" style="background-color: #05050A; border-radius: 8px;">
    <tr>
      <td width="50%" valign="top">
        <ul style="color: #CCCCCC;">
          <li><b style="color: #00E5FF;">Entity Integrity:</b> Enforcing the strict rule that a Primary Key cannot possess a NULL value.</li>
          <li><b style="color: #00E5FF;">Referential Integrity:</b> Ensuring Foreign Keys strictly map to a Primary Key in a related table or remain NULL.</li>
        </ul>
      </td>
      <td width="50%" valign="top">
        <ul style="color: #CCCCCC;">
          <li><b style="color: #00E5FF;">Table Intension:</b> Defining the constant structural schema, name, and laid constraints of a database table.</li>
          <li><b style="color: #00E5FF;">Table Extension:</b> Managing the time-dependent, fluctuating number of tuples (rows) present at any given instance.</li>
        </ul>
      </td>
    </tr>
  </table>
  </blockquote>

          <li><b style="color: #00E5FF;">Virtual Views:</b> Constructing virtual tables (`CREATE VIEW`) based on the result-set of stored SQL statements.</li>
